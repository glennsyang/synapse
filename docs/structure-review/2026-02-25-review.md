# Code Structure Review - 2026-02-25

## Scope

Reviewed maintainability, structure, and performance signals across:

- `src/routes/**` (priority on `+page.server.ts`, `+layout.server.ts`, `+server.ts`)
- `src/lib/**` shared modules, exports, and utilities
- Representative `.svelte` pages/components for lifecycle usage and repeated Tailwind patterns
- Excluded from review: `src/lib/components/ui/**` (shadcn-svelte package primitives)

## Executive Summary

The codebase is generally organized and typed, but there are several high-impact structural issues:

1. **Control-flow bug in multiple `load` functions**: `redirect(...)` is called without `throw`, allowing execution to continue with nullable data.
2. **Error-boundary inconsistency** across server actions (`return { status, error }` vs `fail()`/`error()`/`message()`), making failure behavior harder to reason about.
3. **Meaningful DRY opportunities** in route-server logic (repeated comma-separated parsing and repeated edit-route ownership/load patterns).
4. **Confirmed dead exports/utilities** in `src/lib` that should be removed or integrated.
5. **Type strictness gaps** (`any` usage in shared utility types) and a couple of server/client boundary coupling smells.

## Findings

### DRY & Abstraction

#### 1) Repeated comma-separated parsing logic across many `+page.server.ts` files

- **Severity:** Medium
- **Affected files:**
  - `src/routes/(app)/todos/new/+page.server.ts`
  - `src/routes/(app)/todos/[id]/edit/+page.server.ts`
  - `src/routes/(app)/journal/new/+page.server.ts`
  - `src/routes/(app)/journal/[id]/edit/+page.server.ts`
  - `src/routes/(app)/meditation/routines/new/+page.server.ts`
  - `src/routes/(app)/meditation/routines/[id]/+page.server.ts`
  - `src/routes/(app)/visits/[id]/+page.server.ts`
- **Issue:** Similar `split(',').map(...).filter(...)` transformations are repeated in many actions.
- **Why it matters:** Increases maintenance cost and risks subtle behavioral drift between routes.
- **Recommended fix:** Extract reusable helpers in `$lib/server/` (e.g., `parseCommaList`, `toJsonStringArray`) and standardize usage.

#### 2) Repeated “load entity + ownership check + superValidate” edit-route pattern

- **Severity:** Medium
- **Affected files:**
  - `src/routes/(app)/fitness/weight/[id]/edit/+page.server.ts`
  - `src/routes/(app)/fitness/meals/[id]/edit/+page.server.ts`
  - `src/routes/(app)/fitness/workouts/[id]/edit/+page.server.ts`
  - `src/routes/(app)/todos/[id]/edit/+page.server.ts`
- **Issue:** Edit routes follow highly similar logic with route-specific table/schema differences.
- **Why it matters:** Changes to auth/ownership/loading behavior require repetitive edits and can drift.
- **Recommended fix:** Introduce shared server helpers in `$lib/server/` for fetch-or-redirect and form-init patterns.

#### 3) Repeated page container Tailwind structure across app pages

- **Severity:** Low
- **Affected files:**
  - `src/routes/(app)/todos/+page.svelte`
  - `src/routes/(app)/visits/+page.svelte`
  - `src/routes/(app)/fitness/+page.svelte`
  - `src/routes/(app)/meditation/+page.svelte`
  - `src/routes/(app)/journal/+page.svelte`
- **Issue:** Repeated layout classes like `mobile-container mx-auto w/full max-w-7xl py-4 sm:py-*` appear in more than three pages.
- **Why it matters:** Styling drift risk and repetitive UI scaffolding.
- **Recommended fix:** Create a reusable page-shell wrapper component in `src/lib/components/app/`.

### Error Handling

#### 4) `redirect()` called without `throw` in `load` handlers

- **Severity:** High
- **Affected files:**
  - `src/routes/(app)/todos/[id]/edit/+page.server.ts`
  - `src/routes/(app)/fitness/weight/[id]/edit/+page.server.ts`
  - `src/routes/(app)/fitness/meals/[id]/edit/+page.server.ts`
  - `src/routes/(app)/fitness/workouts/[id]/edit/+page.server.ts`
- **Issue:** `redirect(...)` is invoked but not thrown in missing-entity branches.
- **Why it matters:** Code continues after intended redirect and can dereference nullable entity values, causing runtime failures.
- **Recommended fix:** Replace with `throw redirect(...)` in all affected branches.

#### 5) Inconsistent action error boundary style (`fail`/`message` vs plain object status)

- **Severity:** Medium
- **Affected files (examples):**
  - `src/routes/(auth)/forgot-password/+page.server.ts` (uses `fail()`/`message()`)
  - `src/routes/(app)/todos/new/+page.server.ts` (returns plain `{ form, error, status }`)
  - `src/routes/(app)/fitness/meals/[id]/edit/+page.server.ts` (returns plain `{ form, error, status }`)
  - `src/routes/(app)/journal/[id]/edit/+page.server.ts` (returns plain `{ form, error, status }`)
- **Issue:** Error handling conventions vary significantly by route.
- **Why it matters:** Inconsistent behavior for client error handling and reduced predictability for future contributors.
- **Recommended fix:** Standardize on `fail()` for validation/domain failures and consistent `message()`/`error()` strategy for user/system errors.

#### 6) Legacy error utility bypasses structured logger

- **Severity:** Medium
- **Affected file:**
  - `src/lib/utils/errors.ts`
- **Issue:** `logError()` uses `console.error(...)` directly, bypassing `$lib/utils/logger`.
- **Why it matters:** Inconsistent log shape and reduced observability control.
- **Recommended fix:** Route this utility through `logger.error(...)` or deprecate in favor of logger-only approach.

### TypeScript Strictness

#### 11) `any` usage in shared utility types

- **Severity:** Medium
- **Affected files:**
  - `src/lib/utils.ts`
- **Issue:** Explicit `any` usage with lint suppressions in shared modules.
- **Why it matters:** Weakens type guarantees in reusable code and can hide regressions.
- **Recommended fix:** Replace with constrained generics or `unknown` + narrowing.

#### 12) Repeated non-null assertions on auth user in route loads

- **Severity:** Low
- **Affected files (examples):**
  - `src/routes/(app)/journal/[id]/edit/+page.server.ts`
  - `src/routes/(app)/todos/[id]/edit/+page.server.ts`
  - `src/routes/(app)/fitness/meals/[id]/edit/+page.server.ts`
  - `src/routes/(app)/fitness/weight/[id]/edit/+page.server.ts`
- **Issue:** Frequent `locals.user!` relies on parent layout guarantees.
- **Why it matters:** Increases fragility when routes are moved/reused/tested in isolation.
- **Recommended fix:** Keep strong layout guard but prefer local null-safe helper assertions for clarity.

### SvelteKit Lifecycle

#### 13) Redundant client redirect with `onMount` where server `load` already redirects

- **Severity:** Low
- **Affected files:**
  - `src/routes/(splash)/+page.svelte`
  - `src/routes/(splash)/+page.server.ts`
- **Issue:** Client-side `onMount` redirects authenticated users, while server `load` already handles this.
- **Why it matters:** Can create hydration flicker and duplicate navigation logic.
- **Recommended fix:** Remove client redirect and rely on server load redirect.

#### 14) Server boundary coupling in client components (type imports from server path)

- **Severity:** Low
- **Affected files:**
  - `src/lib/components/app/NavUser.svelte`
  - `src/lib/components/app/AppSidebar.svelte`
- **Issue:** UI components import `User` type from `$lib/server/db/types`.
- **Why it matters:** Couples client component contracts to server-layer module paths.
- **Recommended fix:** Move shared UI-facing user type to `src/lib/types.ts` and import from there.

## Priority Fix Plan

1. **Fix all non-thrown redirects** in affected edit route `load` functions.
2. **Standardize action error boundaries** (`fail`/`error`/`message`) and normalize failure payload shape.
3. **Extract shared route-server helpers** for repeated parsing and entity-load/ownership patterns.
4. **Remove or adopt unused exports** (`getCrudMessage`, `formatError`, `handleAsync`, `withLogging`).
5. **Reduce `any` in shared utility types** and replace with stricter generics/`unknown`.

- Remove clearly unused exports in `src/lib/utils/errors.ts` and `src/lib/utils/logger.ts`.
- Consolidate comma-list parsing helper into `$lib/server/` and adopt in top repeated routes first.
- Drop redundant `onMount` redirect in splash page.
